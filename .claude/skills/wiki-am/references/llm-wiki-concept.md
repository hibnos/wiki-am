# Karpathy LLM Wiki 개념 정리

원문: https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f

## 핵심 아이디어

매번 원본 소스에서 다시 검색(RAG)하는 대신, LLM이 **영속적이고 복리적으로 쌓이는(persistent, compounding) 위키**를 점진적으로 만들고 유지한다. 크로스 레퍼런스는 이미 걸려 있고, 모순은 이미 표시되어 있는 상태로 지식이 축적된다.

> "You never (or rarely) write the wiki yourself — the LLM writes and maintains all of it."

역할 분담:
- **사람**: 소스를 큐레이션하고, 질문하고, 방향을 준다.
- **LLM**: 요약, 크로스 레퍼런스, 분류(filing), 정리(bookkeeping)를 전담한다.

## 3계층 아키텍처

| 계층 | 내용 | 소유자 |
|---|---|---|
| **Raw 소스** | 문서, 논문, 이미지 등 원본. 불변(immutable) — LLM은 읽기만 한다 | 사람 |
| **Wiki** | 요약, 엔티티/개념 페이지, 분석 등 생성된 마크다운. 생성·갱신·일관성 유지 전부 LLM 담당 | LLM |
| **Schema** | 위키 구조·컨벤션·워크플로우를 정의하는 문서 (CLAUDE.md / AGENTS.md) | 사람+LLM 합의 |

## 표준 폴더 구조

```
your-kb/
├── raw/              # 불변 원본 문서
│   ├── assets/       # 이미지, 첨부물
│   └── *.md / *.pdf  # 소스 파일
└── wiki/             # LLM이 생성·유지하는 지식 베이스
    ├── index.md      # 콘텐츠 중심 카탈로그
    ├── log.md        # 시간순 작업 기록
    ├── overview.md   # 종합 페이지
    ├── sources/      # 소스별 요약
    ├── entities/     # 사람, 조직, 도구
    ├── concepts/     # 이론, 방법, 패턴
    └── analyses/     # 비교, 종합 분석
```

## index.md

모든 위키 페이지를 나열하는 콘텐츠 중심 카탈로그. 각 항목은 **링크 + 한 줄 요약 + 선택적 메타데이터(날짜, 소스 수)**. 카테고리별로 정리한다. LLM은 ingest할 때마다 index를 갱신하고, 질문에 답할 때 index를 **가장 먼저** 읽는다.

## log.md

append-only 시간순 기록. 일관된 프리픽스를 써서 표준 도구로 파싱 가능하게 유지한다:

```
## [2026-04-02] ingest | Article Title
```

최근 5개 항목 조회: `grep "^## \[" log.md | tail -5`

## 3대 유지보수 워크플로우

1. **Ingest**: 새 소스를 읽고 → 핵심 정리 → 요약 작성 → 관련 엔티티/개념 페이지 갱신 → 크로스 레퍼런스 유지 → log 기록. 소스 하나가 보통 10~15개 페이지를 건드린다.
2. **Query**: 관련 위키 페이지를 찾아 인용과 함께 답을 종합한다. 가치 있는 탐구 결과는 새 페이지로 다시 파일링해서 지식이 복리로 쌓이게 한다.
3. **Lint**: 주기적 건강 점검 — 모순, 낡은 주장(stale claims), 고아 페이지, 빠진 크로스 레퍼런스, 데이터 공백을 찾는다.

## 페이지 작성 원칙

- 페이지들은 고립된 문서가 아니라 **살아있는 상호 연결 시스템**으로 기능해야 한다.
- 위키 안의 주장은 어느 raw 소스에서 왔는지 추적 가능해야 한다 (인용/링크).
- 모순되는 정보를 발견하면 숨기지 말고 명시적으로 표시한다.
